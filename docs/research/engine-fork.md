Pin: Chromium tag `156.0.8078.120` (newest 156 tag; a 157 branch exists), commit `0729e735c30c850596143183bef1c5642f135659`. **[verified]** = read at the tag and linked to file and line. **[unverified]** = estimate, inference, or not read at the tag. Nothing was built or run. Churn counts are commits on this line since 2026-07-28 (the 152 tag), counted with the GitHub mirror API.

**Answer first.** Patch Chromium inside the renderer (the process that runs the page), at the moment a page commits (hands its finished layers to the compositor, the part that assembles frames). About 60 changed lines in 9 existing files plus about 5,000 new lines **[unverified]**.
- **Tap point (where the page is copied out):** Tap 1, a subclass `LumaLayerTreeHostImpl` of `ClientLayerTreeHostImpl`, created through a 12-line factory hook. It sees vector pictures right after commit, before the engine paints pixels; stock painting keeps running, so screenshots and the pixel fallback still work.
- **Pictures once per font and image:** `SkSerialProcs` swap each font and image for a short id; the bytes cross once on a resource channel and the client acknowledges them.
- **Scrolling from outside:** the root scroller takes `SetSynchronousInputHandlerRootScrollOffset`; other scrollers take `ScrollLayerTo`, then `DidScrollContent` and `SetNeedsCommit`, all public (no edit under `cc/input`). Sticky runs on the client; snap and wheel-blocking keep the engine in the loop.
- **Video:** override the public `GetBaseRendererFactory` with a port of patch 0023's renderer: encoded packets leave over a descriptor the browser hands down, and a hole frame marks the picture's slot. Sound (PCM) comes from the same renderer plus an audio-sink tap.
- **Canvas and WebGL:** pictures cover software 2D canvas only; the rest is read back by the browser through `CopyFromSurface`, which needs no patch for a first version.
- **Docker:** keep the sandbox on with a custom seccomp profile. The renderer cannot open sockets, so everything leaves through the browser. AdGuard needs no patch.
- **Build [unverified]:** `chrome` target at the tag, `gclient sync --no-history`, ccache; about 35 GB source, 40-60 GB output, 4-7 h cold on 8 cores (1-1.5 h on 64), 5-15 min warm.
- **Top risks:** scrollers that cannot scroll locally; sandbox plumbing; the engine still doing its own raster work.

## Serialization
- Contract (PLAN.md, R2): a typeface or image inside a picture is its resource id; `proto::skp` carries the pictures and a side channel carries the bytes once.
- **[verified]** Skia's hook for that is `SkSerialProcs` (`include/core/SkSerialProcs.h` at Skia `9d96dfeb451c`): `fPictureProc`, `fImageProc`, `fTypefaceProc` with a context pointer each. The header says a returned data object "will be used (even if it is zero-length)" and null means Skia's default action, so a proc can return a small id blob and the bytes ship separately. `SkDeserialProcs` has the matching `fImageProc`, `fImageDataProc`, `fTypefaceStreamProc` on the client.
- **[verified]** Reusable code: `MakeSerialProcs` ([`serial_utils.h:103`](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.120/components/paint_preview/common/serial_utils.h#103)) (`serial_utils.{h,cc}`, 347 lines) with three contexts. `SerializeTypeface` dedups by `uniqueID()` and subsets with HarfBuzz (`SubsetFont` ([`subset_font.cc:68`](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.120/components/paint_preview/common/subset_font.cc#68)), which keeps glyph ids via `HB_SUBSET_FLAGS_RETAIN_GIDS` ([`subset_font.cc:87`](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.120/components/paint_preview/common/subset_font.cc#87)), so a subset and the full font share glyph ids). `SerializeImage` returns the encoded bytes for BMP, GIF, PNG, JPEG and WebP and PNG at quality 100 otherwise. `MakeDeserialProcs` exists. Four commits since 151, two since 152.
- **Once per font and image [design, unverified until measured]:** key each typeface and image by a 128-bit content hash, memoized per `SkTypeface::uniqueID()` or `SkImage::uniqueID()` so no file is rehashed. The proc returns `{kind, hash}` (about 17 bytes). The first use of a hash puts `{hash, bytes}` on the resource channel; the client acknowledges stored hashes at connect so a reconnect resends nothing, and keeps fonts on disk by hash.
- **Typeface blobs must carry [unverified]:** the TTC index and variation coordinates (from `SkTypeface::openStream` and `getVariationDesignPosition`); synthetic bold and skew live in `SkFont`, inside the picture. Web fonts arrive as sfnt streams. System fonts (fontconfig in the container) must be shipped too: the TV has neither the CJK nor the emoji fonts. A subset keeps first paint small, then the full font follows under the same id because gids are retained.
- **Images [verified]:** encoded bytes come from `refEncodedData()` with no decode (previous section). Decoded-only images (canvas, `ImageBitmap`) go as PNG. Animated GIF, WebP and AVIF pick their frame through `ImageAnimationController`, so the picture re-serializes per frame unless frame index and image become separate ops [unverified].
- **Cost [unverified]:** serializing is one `Raster` pass into an `SkPictureRecorder` plus `SkPicture::serialize`; cost per layer is not measured (R2 times replay and 512 x 512 tiles).
- **Version rule:** the client's Skia must read the engine's SKP version (R2 desk-checks `SkPicture` `kMin_Version`).
- **Not representable [verified]:** paint-worklet images, `DrawSkottieOp` animation after serialization (baked at the sampled time), and filters that read the backdrop outside the picture (those live in effect nodes, which are on the wire).

## Sandbox in Docker
**Answer.** The sandbox works as non-root if the container may create user namespaces (private views of users and processes). Docker's default seccomp profile (the kernel's system-call filter) blocks that, so Chromium stops with "No usable sandbox!". Fix: a custom seccomp profile, no extra capabilities; `--no-sandbox` is the last resort. The renderer, where the `cc` hooks run, cannot open sockets or files, so every byte to the TV leaves through the browser process.
- **[verified]** Start-up order in `Init` ([`zygote_host_impl_linux.cc:86`](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.120/content/browser/zygote_host/zygote_host_impl_linux.cc#86)): root without `--no-sandbox` exits; the namespace sandbox is used if `CanCreateProcessInNewUserNS` ([`credentials.cc:267`](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.120/sandbox/linux/services/credentials.cc#267)) succeeds; else the setuid helper; else fatal "No usable sandbox!". The sandbox then launches children with `CLONE_NEWUSER | CLONE_NEWPID | CLONE_NEWNET` (`ns_types` ([`namespace_sandbox.cc:142`](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.120/sandbox/linux/services/namespace_sandbox.cc#142))), calls `unshare(CLONE_NEWUSER)` (`sys_unshare` ([`credentials.cc:301`](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.120/sandbox/linux/services/credentials.cc#301))) and `chroot("/proc/self/fdinfo/")` (`sys_chroot` ([`credentials.cc:56`](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.120/sandbox/linux/services/credentials.cc#56))).
- **[verified]** Docker's default profile ([`moby/profiles` default.json](https://github.com/moby/profiles/blob/main/seccomp/default.json), not the Chromium tag): `clone` is allowed only when none of the namespace flags (mask `0x7E020000`) is set; `clone3` returns ENOSYS; `unshare`, `setns`, `mount` need `CAP_SYS_ADMIN`; `chroot` needs `CAP_SYS_CHROOT`, so `--cap-drop=ALL` removes it; `memfd_create`, `seccomp`, `prctl` are allowed. A profile that adds `clone` with namespace flags, `unshare` and `chroot` should be enough **[unverified]**; the first run shows any further denial.
- **Options:** custom seccomp profile (non-root; container processes may then create user namespaces, more kernel attack surface); `--cap-add SYS_ADMIN` (far broader, avoid); setuid `chrome-sandbox` (legacy, "almost but not completely removed" in `docs/linux/suid_sandbox_development.md`; **[unverified]** against `no-new-privileges`); `--no-sandbox` (skips everything, **[verified]** at the top of `Init`).

**Implementation order, smallest useful increment first** (gate names are PLAN's):
1. **No patch (F1):** build `chrome` at the tag, run it in Docker with the sandbox on, load AdGuard, probe WebGL and `navigator.gpu`, read Tap 0 (CDP `LayerTree`). Replaces every build estimate with a measurement.
2. **Seam:** factory hook, a subclass that only counts hook calls, descriptor switch. Flag off must equal the stock build and open no socket (F2 gate).
3. **Scene dump, sandbox off for this step only:** at `CommitComplete`, write layers, trees, regions and per-layer SKP with id blobs to a file; `tap-dump` replays it (R2's version rule).
4. **Pipe:** descriptor, browser relay, resource acks and flow control, deltas; sandbox back on; stitch widgets by `FrameSinkId`.
5. **Scroll (F3):** `SetScrollOffsets` for the root and composited inner scrollers, client sticky, wheel-blocking through `OnInputEventAck`, snap replay. Gate: scripted offsets move `scroll-` pages and fire listeners.
6. **Animations (F3):** curves, start times, clock offset, scroll timelines. S2: a transform animation runs with the engine stopped.
7. **Pixel fallback (E9):** browser `CopyFromSurface` for named rectangles and canvas and WebGL layers. GL gate.
8. **Page info:** focus, text input, selection, cursor.
9. **Media (VID):** `GetBaseRendererFactory` override with the 0023 port, media descriptor, new messages (PTS with epoch, flush, start, pause, rate, volume, TV clock back), then the PCM tap.
10. **Later:** popups and `<select>`, the extension prompt patch, official build flags.

**Risks**, top three first:
1. **Scrollers that cannot scroll locally** **[unverified]**: raster-inducing and main-thread scrollers are baked into the parent picture, so each scroll step needs the engine. How many real pages hit this is unmeasured; it decides how much of S2 and P2 holds.
2. **Sandbox plumbing** **[unverified]**: the minimal seccomp set, `user.max_user_namespaces` on the host, and descriptor passing through the zygote are untested; `--no-sandbox` is the fallback.
3. **The engine still does its own work:** raster and Viz draw run for every frame the engine makes. Driving the engine's frames from the client clock (F3) needs BeginFrame control, unread for new headless **[unverified]**.
4. Popups, `<select>` and out-of-process iframes are separate widgets; stitching by `FrameSinkId` **[unverified]**.
5. Paint-worklet images and animation curves of unsupported kinds (SIZE, RECT, FILTER, scroll offset) have no stock serializer.
6. Flow control: a slow client must not grow engine memory; acks and drop rules are design only.
7. Churn: `chrome_content_browser_client.cc` had 110 commits in the window; keep the hunk to one call and rebase per milestone.
8. Build size and time are estimates until step 1.
